---
title: "GET /opportunities — List All Partner Opportunities"
sidebarTitle: "List Opportunities"
description: "List all registered opportunities for your partner account. Filter by pipeline stage, sort by date, and paginate through results using limit and offset."
---

Retrieve a paginated list of all opportunities registered by your partner account, with optional filters to narrow results by pipeline stage. Use this endpoint to build dashboards, sync your CRM, or audit which deals require follow-up. Results are sorted by creation date by default and support limit/offset pagination.

## Request

```http
GET https://api.ecosystem.rhmbs.app/v1/opportunities
```

### Query Parameters

<ParamField query="stage" type="string">
  Filter results to only opportunities in a specific pipeline stage. Omit this parameter to return opportunities across all stages.

  Accepted values: `submitted`, `in_triage`, `ae_assigned`, `se_engaged`, `pending_installation`, `scheduled`, `installed`, `closed_lost`.
</ParamField>

<ParamField query="limit" type="integer" default="20">
  Number of opportunity objects to return per page. Maximum value is `100`.
</ParamField>

<ParamField query="offset" type="integer" default="0">
  Zero-based index of the first result to return. Use in combination with `limit` to paginate through large result sets.
</ParamField>

<ParamField query="sort" type="string" default="created_at_desc">
  Sort order for results. Accepted values:

  - `created_at_desc` — most recently created first (default)
  - `created_at_asc` — oldest first
</ParamField>

## Example Request

The following request retrieves up to 10 opportunities that are currently in the `pending_installation` stage.

```bash cURL
curl --request GET \
  --url 'https://api.ecosystem.rhmbs.app/v1/opportunities?stage=pending_installation&limit=10' \
  --header 'Authorization: Bearer <api-key>'
```

<Tip>
  To iterate through all opportunities, increment `offset` by your `limit` value on each request until `has_more` is `false`.
</Tip>

## Response

A successful request returns `200 OK` with a paginated result object.

### Response Fields

<ResponseField name="data" type="array">
  Array of opportunity objects matching the query. Each object contains the same fields as the [Get Opportunity](/api-reference/opportunities/get) response.
</ResponseField>

<ResponseField name="total_count" type="integer">
  Total number of opportunities matching the applied filters, regardless of pagination. Use this value to calculate the number of pages.
</ResponseField>

<ResponseField name="limit" type="integer">
  The `limit` value applied to this request.
</ResponseField>

<ResponseField name="offset" type="integer">
  The `offset` value applied to this request.
</ResponseField>

<ResponseField name="has_more" type="boolean">
  `true` if there are additional results beyond the current page. `false` if this page contains the last results.
</ResponseField>

## Error Responses

| Status | Code | Description |
|--------|------|-------------|
| `401 Unauthorized` | `unauthorized` | The API key is missing, expired, or invalid. Check that your `Authorization` header is correctly formatted. |
| `400 Bad Request` | `invalid_stage` | The value provided for the `stage` query parameter is not a recognized pipeline stage. Check the list of accepted values and retry. |
