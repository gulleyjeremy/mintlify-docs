Retrieve a list of all users in your partner organization. Use this endpoint to sync your internal directory with Ecosystem portal access, audit who holds active credentials, or identify team members who have been invited but have not yet completed sign-in. Results are paginated and can be filtered by role.

## Request

**Method and URL**

```http
GET https://api.ecosystem.rhmbs.app/v1/partners/users
```

**Headers**

| Header          | Value                     |
| --------------- | ------------------------- |
| `Authorization` | `Bearer <api-key>`        |

**Query Parameters**

<ParamField query="limit" type="integer" default="20">
  Maximum number of users to return per page. Accepted range is `1`–`100`. Defaults to `20`.
</ParamField>

<ParamField query="offset" type="integer" default="0">
  Number of users to skip before beginning the result set. Use with `limit` to paginate through large lists. Defaults to `0`.
</ParamField>

<ParamField query="role" type="string">
  Filter results by user role. Accepted values are `admin` or `member`. Omit this parameter to return users of all roles.
</ParamField>

## Example Request

```bash cURL
curl --request GET \
  --url "https://api.ecosystem.rhmbs.app/v1/partners/users?limit=20&offset=0&role=admin" \
  --header "Authorization: Bearer <api-key>"
```

## Response

A successful request returns a `200 OK` status with a paginated JSON object. The `data` array contains user objects for the current page.

**Pagination Wrapper**

<ResponseField name="data" type="array" required>
  Array of user objects for the current page.
</ResponseField>

<ResponseField name="total_count" type="integer" required>
  Total number of users in your partner organization matching the applied filters.
</ResponseField>

<ResponseField name="limit" type="integer" required>
  The `limit` value applied to this request.
</ResponseField>

<ResponseField name="offset" type="integer" required>
  The `offset` value applied to this request.
</ResponseField>

<ResponseField name="has_more" type="boolean" required>
  `true` if additional pages of results exist beyond the current page; `false` if this is the last page.
</ResponseField>

**User Object Fields**

<ResponseField name="id" type="string" required>
  Unique identifier for the user.
</ResponseField>

<ResponseField name="name" type="string" required>
  Full name of the user.
</ResponseField>

<ResponseField name="email" type="string" required>
  Email address associated with the user's Ecosystem portal account.
</ResponseField>

<ResponseField name="role" type="string" required>
  User's role within your partner organization. One of `admin` or `member`.
</ResponseField>

<ResponseField name="status" type="string" required>
  Current account status. `active` means the user has completed sign-in at least once. `pending` means the user has been invited but has not yet logged in.
</ResponseField>

<ResponseField name="created_at" type="string" required>
  ISO 8601 datetime representing when the user was added to the organization (e.g., `2024-01-22T09:15:00Z`).
</ResponseField>

<Note>
  User management — including inviting new users, removing existing users, and changing roles — is handled through the Ecosystem portal UI at [https://ecosystem.rhmbs.app](https://ecosystem.rhmbs.app). This endpoint is **read-only**.
</Note>

## Error Responses

<AccordionGroup>

  <Accordion title="401 Unauthorized">
    The API key is missing or invalid. Verify that your `Authorization` header includes a valid, active Bearer token.

    ```json
    {
      "error": "unauthorized",
      "message": "A valid API key is required to access this endpoint."
    }
    ```
  </Accordion>

  <Accordion title="403 Forbidden">
    The API key belongs to a user with the `member` role. Listing partner users requires the `admin` role. Use an API key generated by an admin account to call this endpoint.

    ```json
    {
      "error": "forbidden",
      "message": "Admin role required. Members cannot list partner users."
    }
    ```
  </Accordion>

</AccordionGroup>
